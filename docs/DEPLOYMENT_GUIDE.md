# Deployment Guide

Step-by-step guide from this repository to a live site using **Render** (backend + frontend), **Neon** (PostgreSQL), and **Cloudflare R2** (media storage). An alternative all-in-one **Docker + nginx** deploy is covered in [Step 5B](#option-b-docker--nginx-on-one-vps).

Other docs: [Project Overview](PROJECT_OVERVIEW.md) · [Backend Architecture](BACKEND_ARCHITECTURE.md) · [Frontend Architecture](FRONTEND_ARCHITECTURE.md) · [Admin Guide](ADMIN_GUIDE.md)

---

## Architecture

```
Browser ──► fiestagastro.dev (Render Static Site / nginx)
              │
              │  VITE_API_URL = https://<backend>.onrender.com/api/v1/   (CORS requests)
              ▼
        Backend (Render Web Service, Docker)   ──►  Neon PostgreSQL
              │                                      (direct endpoint, SSL)
              ▼
        Cloudflare R2 (signed media URLs)
```

| Layer | Production choice | Local dev (Docker Compose) |
|-------|-------------------|---------------------------|
| Frontend | Render Static Site (nginx/Docker variant optional) | `frontend` service (nginx) on `:80` |
| Backend | Render Web Service (Docker image) | `backend` service on `:8000` |
| DB | Neon (serverless Postgres) | `db` service (postgres:16) in `pgdata` volume |
| Media | Cloudflare R2 | R2 (already set up) |

## Prerequisites — Accounts

| Account | Used for | Free tier |
|---------|----------|-----------|
| [Cloudflare](https://dash.cloudflare.com/sign-up) | R2 bucket + API token (media storage) | R2: 10 GB storage + 1M class‑B ops/mo |
| [Neon](https://console.neon.tech) | Serverless PostgreSQL database | 0.5 GB storage |
| [Render](https://dashboard.render.com) | Backend Web Service + frontend hosting | 750 hours/mo (no shell access) |

You also need a domain (e.g. `fiestagastro.dev`) to attach to the frontend — the free `*.onrender.com` URLs work too, but SEO/HTTPS on a custom domain is preferable. Subdomains you'll typically reserve:

- `api.yourdomain.com` → backend (or keep the `.onrender.com` URL)
- `yourdomain.com` / `www.yourdomain.com` → frontend

## 1. Cloudflare R2 (media storage)

1. **Create bucket** — Cloudflare Dashboard → R2 → **Create bucket** (name e.g. `cafe-media`; region "APAC" is fine, use **EU** for best latency).
2. **Create API token**: R2 → **Manage R2 API Tokens** → **Create API token** with Object Read & Write + Read. Save `ACCESS_KEY_ID` and `SECRET_ACCESS_KEY` now — they are shown **only once**.
3. **Publish via custom domain** (optional but recommended): **Settings → Public access → Domain** → add `media.yourdomain.com` (proxied), or use the auto-generated `*.r2.cloudflarestorage.com` URL.
4. The bucket **must be private** (`default_acl: "private"` in settings) — media is served via **signed URLs** generated by django-storages.

You now have 4 values (token pair, bucket name, endpoint URL). Endpoint URL is either:

- `https://<account-id>.r2.cloudflarestorage.com` (R2 endpoint) — use for signed URLs, or
- your custom domain `https://media.yourdomain.com` (only if you connected one — signed URLs still work; add the domain to `R2_ENDPOINT_URL` instead of the regional endpoint).

## 2. Neon (PostgreSQL)

1. Dashboard → **Create project** → pick a region close to you → **Create**.
2. Open the project → **Connect** → copy a connection string:
   ```
   postgres://neondb_owner:PASSWORD@ep-xxxx-yyyy.eu-central-1.aws.neon.tech/cafe_db?sslmode=require
   ```
3. Split it into the `DATABASE_*` variables the backend expects (Django reads them individually — there is no `DATABASE_URL` support):

   | Env var | Value from the string |
   |---------|----------------------|
   | `DATABASE_NAME` | `cafe_db` (create it via the Neon SQL editor if not present: `CREATE DATABASE cafe_db;`) |
   | `DATABASE_USER` | `neondb_owner` |
   | `DATABASE_PASSWORD` | the `PASSWORD` part |
   | `DATABASE_HOST` | `ep-xxxx-yyyy.eu-central-1.aws.neon.tech` (the **direct** endpoint — see below) |
   | `DATABASE_PORT` | `5432` |
   | `PGSSLMODE` | `require` (Neon only accepts SSL connections — for `psql`/`pg_dump` on the CLI; Django connects via the backend's own SSL handling when using the direct host) |

> **Direct vs pooled:** Neon offers two hostnames — a **direct** one (`ep-....neon.tech`) and a **pooled** one (`ep-....pooler.neon.tech`, PgBouncer). Use the **direct** host for app traffic: our settings keep connections alive (`CONN_MAX_AGE=600`) and PgBouncer's *transaction* mode breaks session features (and some migrations). Typo watch: the host contains hyphens, e.g. `ep-flat-boat-xxxx.c-6.eu-central-1...` (not `c6...`/`ceu...`).
>
> **Test from your machine (postgres client):**
> ```bash
> PGPASSWORD=$DATABASE_PASSWORD psql -h $DATABASE_HOST -U $DATABASE_USER -d $DATABASE_NAME -c "SELECT 1;"  # → CONNECTION OK
> ```

## 3. Render backend (Django Web Service)

1. **Push this repo to GitHub** (Render deploys from Git automatically).
2. Dashboard → **New → Web Service** → pick the repo.
3. Settings:
   - **Root Directory**: `src/backend` (the Dockerfile + entrypoint.sh live there)
   - **Runtime**: auto-detected from `src/backend/Dockerfile` → "Docker"
   - **Start command**: leave empty (the image's `ENTRYPOINT` runs `entrypoint.sh` — it applies migrations, then starts Gunicorn)
4. **Environment variables** (add via the dashboard):

   | Variable | Value |
   |----------|-------|
   | `SECRET_KEY` | a long random string (generate one, keep it secret) |
   | `DEBUG` | `False` |
   | `ALLOWED_HOSTS` | `api.yourdomain.com,<your-service>.onrender.com` (comma-separated) |
   | `DATABASE_NAME` / `DATABASE_USER` / `DATABASE_PASSWORD` / `DATABASE_HOST` / `DATABASE_PORT` | from [Step 2](#2-neon-postgresql) |
   | `CORS_ALLOWED_ORIGINS` | `https://fiestagastro.dev,https://www.fiestagastro.dev` (frontend URLs) |
   | `CSRF_TRUSTED_ORIGINS` | same frontend URLs (if you ever allow non-GET via the admin) |
   | `R2_ACCESS_KEY_ID` | from [Step 1](#1-cloudflare-r2-media-storage) |
   | `R2_SECRET_ACCESS_KEY` | from Step 1 |
   | `R2_BUCKET_NAME` | e.g. `cafe-media` |
   | `R2_ENDPOINT_URL` | e.g. `https://<account-id>.r2.cloudflarestorage.com` |
   | `GUNICORN_WORKERS` | `2`–`4` (free tier memory-bound) |

5. **Deploy**. On first boot `entrypoint.sh` runs `manage.py migrate --noinput` automatically — no manual steps.

> ⚠️ **Render has no shell** (free tier). For one-off Django management commands (data import, `createsuperuser`) run them locally against the Neon DB — see [Step 4](#4-optional-import-the-mockup-data).

**Verify:** open `https://<service>.onrender.com/api/v1/health/` → `{"status": "ok", ...}`, then `.../api/v1/menu/categories/` → JSON list (empty DB still returns `[]`).

## 4. (Optional) Import the mock data

`cafe_data.json` contains 15 menu categories + 49 products with Romanian names, slugs, and **signed R2 image URLs that do not exist in the bucket** (the fixture was written for the local demo). Load it if you want a working menu skeleton, then **re-upload every image** in the admin (`img_src` field) — otherwise products render with broken/blank images.

Render has no shell, so run these locally **against the Neon DB**:

```bash
# Option A — Docker Compose (project already has a backend image)
docker compose run --rm \
  -e DATABASE_NAME=cafe_db \
  -e DATABASE_USER=neondb_owner \
  -e DATABASE_PASSWORD='<neon-password>' \
  -e DATABASE_HOST=ep-xxxx-yyyy.eu-central-1.aws.neon.tech \
  -e DATABASE_PORT=5432 \
  -e PGSSLMODE=require \
  --entrypoint "" \
  backend python manage.py migrate --noinput

docker compose cp cafe_data.json backend:/app/
docker compose run --rm \
  -e DATABASE_NAME=cafe_db -e DATABASE_USER=neondb_owner \
  -e DATABASE_PASSWORD='<neon-password>' \
  -e DATABASE_HOST=ep-xxxx-yyyy.eu-central-1.aws.neon.tech \
  -e DATABASE_PORT=5432 -e PGSSLMODE=require \
  --entrypoint "" \
  backend python manage.py loaddata cafe_data.json
```

```bash
# Option B — bare venv (uv)
cd src/backend
cat > .env << 'EOF'
SECRET_KEY=anything-for-local-tools
DATABASE_NAME=cafe_db
DATABASE_USER=neondb_owner
DATABASE_PASSWORD=your-neon-password
DATABASE_HOST=ep-xxxx-yyyy.eu-central-1.aws.neon.tech
DATABASE_PORT=5432
EOF
uv sync
uv run python manage.py migrate --noinput
uv run python manage.py loaddata cafe_data.json
```

Then create the admin account (required — the fixture has **no superuser**):

```bash
# (same env vars as above; works with both Option A and B)
uv run python manage.py createsuperuser   # or in compose: ... backend python manage.py createsuperuser
```

After the import, complete the site via the admin at `https://<service>.render.com/cafe-admin/` — see [Admin Guide → Quick Start](ADMIN_GUIDE.md#quick-start--what-must-be-created): Site Settings (contact info), Site Image (`logo`), and the 4 required Pages. Skip the image re-uploads if you'd rather do it later.

## 5. Frontend

### Option A — Render Static Site

1. Dashboard → **New → Static Site** → your repo.
2. Settings:
   - **Root Directory**: `src/frontend`
   - **Build Command**: `npm run build` (runs `tsc` → `fetch-favicon.mjs` → `generate-seo.mjs` → `vite build`)
   - **Publish Directory**: `dist`
3. **Environment variables** (used at build time — Vite bakes them into the bundle):

   | Variable | Value |
   |----------|-------|
   | `VITE_API_URL` | `https://<backend-service>.render.com/api/v1/` (or your api subdomain) |
   | `VITE_SITE_URL` | `https://fiestagastro.dev/` (drives robots.txt, sitemap.xml, canonical URLs) |

4. **SPA fallback** — Render does **not** read `.netlify`-style `_redirects` files; add a rule in the dashboard: **Static Site → Redirects / Rewrites**:
   - Source: `/*` · Destination: `/index.html` · Action: **Rewrite**
   This makes client-side routes like `/content/despre-noi` load (a direct hit otherwise returns 404).
5. **Custom domain** (optional, recommended): **Settings → Domains → Add domain** → `fiestagastro.dev`, then point the DNS `CNAME` at the site's `*.onrender.com` hostname.

### Option B — Docker + nginx (VPS)

The repo ships with a full stack in `docker-compose.yml` (db + backend + frontend). Deploy on a VPS any Docker host:

```bash
git clone <repo> Cafe_site && cd Cafe_site
# 1. root .env (db credentials)
cat > .env << 'EOF'
POSTGRES_DB=cafe_db
POSTGRES_USER=postgres
POSTGRES_PASSWORD=postgres
EOF
# 2. src/backend/.env → same as Step 3's Render env table, but
#    DATABASE_HOST=db, ALLOWED_HOSTS=*, DEBUG=True (behind your reverse proxy), etc.
docker compose build
docker compose up -d
```

| | Docker + nginx | Render Static Site |
|---|---|---|
| API base URL | build-arg `VITE_API_URL: /api/v1/` (nginx proxies → backend) | full backend URL (CORS) |
| SPA fallback | `try_files ... /index.html` in nginx.conf | dashboard Rewrite rule |
| nginx control | full | none |
| TLS | your reverse proxy (e.g. Caddy) in front of `:80` | automatic on Render |

Frontend differs only in `VITE_API_URL`: relative `/api/v1/` in compose, absolute backend URL on Render (see [Frontend Architecture → Docker](FRONTEND_ARCHITECTURE.md#docker--docker-compose)).

## 6. Wiring & final checks

| Check | How |
|-------|-----|
| Backend health | `curl https://<backend>/api/v1/health/` |
| CORS | `curl -H "Origin: https://fiestagastro.dev" -I https://<backend>/api/v1/menu/categories/` → expect `access-control-allow-origin` header |
| ALLOWED_HOSTS | visiting `n/health` from a host not in the list → `400`; add it to the var + redeploy |
| Frontend | load `https://fiestagastro.dev` — check Network tab: API calls reach the backend (`api/v1/...`) and images load from R2 signed URLs |
| Admin | `https://<backend>/cafe-admin/` logs in; media uploads land in the R2 bucket |

**Custom domains**: `api.yourdomain.com` → CNAME → `<backend>.onrender.com`; `fiestagastro.dev` → CNAME → `<site>.onrender.com` (have Render auto-request the HTTPS cert for both).

## Troubleshooting

| Symptom | Cause / Fix |
|---------|-------------|
| Build fails: `VITE_API_URL is required` | Missing env var at build time (Render dashboard / compose build arg) |
| `/` loads, deep links 404 | SPA fallback missing → add the `/*`→`/index.html` Rewrite (Static Site) or verify nginx `try_files` |
| Frontend API calls fail (CORS) | `CORS_ALLOWED_ORIGINS` missing the exact origin (scheme + host, no trailing slash) |
| `400 Bad Request` from backend | hostname not in `ALLOWED_HOSTS` |
| Neon connection refused | Verify host typo (`c-6.eu-...` not `c6.ceu-...`), pooled vs direct + SSL, `DATABASE_PORT` |
| Migrations fail on Neon | Needs SSL; run `migrate` locally with `PGSSLMODE=require` (Step 4) |
| Admin CSRF errors | add backend domain to `CSRF_TRUSTED_ORIGINS` |
| Signed R2 URLs won't open | `R2_ENDPOINT_URL` must match the token/bucket region; all `R2_*` vars set; server clock correct |
| Logs | Render → service → **Logs**; for Docker: `docker compose logs -f backend` |
